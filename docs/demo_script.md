# Demo Script (5 minutes)

Goal: a judge understands in 30 seconds that cameras only record, and in 4 more
minutes that this system recognizes and responds.

**Before you start**

- [ ] Backend running (`make api`) and healthy at `http://localhost:8000/health`
- [ ] Dashboard running (`make ui`) at `http://localhost:8501`
- [ ] Database seeded (`make seed`) so incidents exist even if the demo machine is slow
- [ ] A test video ready in `samples/videos/`
- [ ] Backup recording of the demo playing on a second device
- [ ] Ollama running *only if* you plan to show the LLM explanation; the template
      fallback is fine and never fails

---

## 1. Problem — 30 seconds

> "Ring and every other camera records what happened. If someone takes a package at
> 2pm, the homeowner finds out at 6pm — or never. Cameras are passive. We built a
> system that *recognizes what is happening and responds*."

**On screen:** the Live Monitor page, video uploaded, protection idle.

**Do not** explain the stack yet.

---

## 2. Live demo — 2 minutes 30 seconds

| Step | Action | What the judge should see |
|---|---|---|
| 1 | Upload `samples/videos/porch_theft.mp4` (or the local test clip) | Video appears, status `UPLOADED` |
| 2 | Click **Simulate delivery** | Protection card flips to `PROTECTION_ACTIVE`, timer starts, source shown as *Simulated delivery* |
| 3 | Click **Analyze** | Progress bar moves, annotated video plays with green boxes on people and blue boxes on the package, track IDs and the protection zone overlay |
| 4 | Wait for the suspicious behaviour | Live event feed scrolls: `PACKAGE_DETECTED` → `PERSON_NEAR_PACKAGE` → `LOITERING_DETECTED` → `PACKAGE_INTERACTION` → `PACKAGE_REMOVED` |
| 5 | Incident appears | Severity badge, reason codes, event timeline, evidence clip |

**Narrate while it runs:**

> "The detector finds the package and the people. The tracker keeps stable IDs. The
> classifier turns those into events. And these events — not the model, not an LLM —
> feed a deterministic rule engine."

**If analysis is slow:** the effective FPS is what matters. Point at the frame counter.
Do not apologise; explain the trade-off (stride + small model on CPU).

---

## 3. Why it was flagged — 45 seconds

Open the incident detail.

> "One incident, not fifty. It is de-duplicated by session, person track and reason
> group with a 30-second cooldown. Here are the reason codes — loitering over
> threshold, package interaction, package removed — and here are the exact event IDs
> that triggered them. Every alert is auditable."

Then the evidence clip and the explanation:

> "The clip is cut from the original video, five seconds either side of the incident,
> with faces blurred. The explanation is generated by a local LLM from a structured
> summary of these events — it can only describe what happened, it can never create
> an incident and it can never run an action. And the wording is deliberately
> 'potential package theft, for review' — never 'thief detected'."

**If Ollama is down:** "This is the deterministic template fallback — the system never
depends on the LLM being up."

---

## 4. Ring integration — 45 seconds

Open the Ring status card.

> "All Ring access goes through one adapter interface, so the AI pipeline does not
> care what the environment provides. Here is exactly what is connected right now."

Then read the table out loud, truthfully:

| Capability | Say |
|---|---|
| Device status | Real, if the real adapter is configured — show the live value |
| Device events | Real or simulated — be explicit |
| Supported action | Only what the environment actually allows |

> "Where the environment does not expose a capability, we label it Simulated rather
> than pretending. Everything that is simulated is marked in the UI and in the data."

**Never** claim a capability is real unless you can show it working.

---

## 5. Privacy and safety — 30 seconds

> "Video is processed and stored locally. Nothing is uploaded to an external AI
> service. Faces are blurred in exported evidence. There is no face recognition and
> nobody is ever identified. The system never contacts police automatically and never
> accuses anyone. Sensitive actions need homeowner confirmation, and only allowlisted
> actions can run. The incident logic is deterministic and every escalation is logged
> with reason codes."

**On screen:** the privacy and safety page or the notification history with the
"Simulated" badges.

---

## 6. Roadmap — 15 seconds

> "Next: live streams instead of prerecorded video, real Ring device actions on
> incident, a real notification channel, multi-camera and multi-package support, and
> a real deterrence escalation path. Today, it is a working end-to-end prototype
> running on real video."

---

## Backup plan

| Problem | Response |
|---|---|
| Backend is down | Restart it, keep talking; the seeded incidents still show on the dashboard |
| Video does not analyse | Use the seeded incident from `make seed`; the story is identical |
| Ollama is down | Template fallback, already rehearsed |
| Ring real adapter fails | Show the local adapter card and say plainly what is and is not connected |
| Everything fails | Play the backup recording and continue the pitch |

## Checklist before the pitch

- [ ] `make test` and `make lint` are green on the demo machine
- [ ] Demo video is a known-good file on the machine (not streamed)
- [ ] `.env` contains no real secrets committed to git
- [ ] The dashboard is on the "Incidents" page pre-seeded with one incident
- [ ] Backup recording is loaded and plays
